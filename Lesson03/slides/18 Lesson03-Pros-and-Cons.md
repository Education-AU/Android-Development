The activity approach seems to be elaborate. But it could be simplified somewhat reusing some of the code.


The main problem is that we need to manage activities on the stack. But we do not have to manage a state and a when
statement in the same way.

The state approach does not make new activities, so it corresponds to a single page (screen) app. But we need to manage
a state and a potentially elaborate one at that when a lot of screens are involved.

The problems of the state-management are addressed in the navigation framework
